There are three UI loading glitches that need to be debugged and fixed. Each one is a separate issue:

Glitch 1: Flash on initial page load. When typing factorflux.io in the browser and pressing enter, there is a brief visual glitch before the login page renders. This is likely the browser showing an unstyled or partially loaded state before React hydrates and the CSS loads. To fix this: add a simple loading screen or splash screen that shows immediately via inline CSS in index.html — just the FactorFlux logo centered on a white or dark background. This shows instantly because it is pure HTML/CSS with no JavaScript needed. Then once React finishes loading, it replaces the splash with the actual login page. The splash screen should be embedded directly in the index.html file, not in a React component, so it renders before any JavaScript loads.

Glitch 2: Delay between login and dashboard. After clicking Sign In, there is a noticeable delay before the dashboard appears. Debug this by checking what happens between successful authentication and dashboard render. Likely causes: the dashboard component is lazy-loaded but the chunk is large, or the dashboard makes multiple API calls that all need to complete before it renders. To fix: preload the dashboard chunk during the sign-in animation (we already added this — verify it is actually working). Make sure dashboard API calls run in parallel not sequentially. Add a loading skeleton for the dashboard that renders immediately while data fetches in the background — show the layout structure with placeholder content so the user sees something instant.

Glitch 3: Delay when navigating between pages. Clicking sidebar links to go from one page to another has a slight delay before the new page renders. This is likely because each page is lazy-loaded and the chunk needs to download on first visit. To fix: add prefetching — when the user hovers over a sidebar link, start loading that page’s chunk immediately so it is ready by the time they click. Also add a lightweight page transition skeleton that shows instantly on click so navigation feels immediate even if the chunk takes a moment.

For all three: add loading skeletons or transition states so the user never sees a blank screen or a flash. The goal is perceived performance — something should always be visible and it should feel instant even if data is still loading in the background. Do NOT touch the neumorphic theme or any existing styles — this is performance and loading states only.
