---
name: Vault entry IDs
description: Legacy client_vault primary-key behavior that can break all new Vault entries.
---

Keep the client Vault primary key auto-generated with a PostgreSQL `GENERATED BY DEFAULT AS IDENTITY` column and represent it as an integer identity in the application schema. Do not model it as `serial`.

**Why:** A required integer ID with no generator makes Vault inserts fail after encryption. Modeling an existing integer as `serial` also makes Publish emit invalid `ALTER COLUMN ... TYPE serial`, because `serial` is creation-time shorthand rather than a PostgreSQL type.

**How to apply:** Preserve identity metadata during schema synchronization. Confirm automatic inserts work and verify the Publish diff uses `ADD GENERATED ... AS IDENTITY`, never `TYPE serial`.
